光纤陀螺的实验台需要一套后端计算服务，用来根据线圈几何和输入角速度还原 Sagnac 干涉相位，并反过来由测得的相位标定出角速度。它是一个纯粹的干涉陀螺计算内核，只通过 HTTP 接口工作，没有网页界面，也不是罗盘应用或航迹显示，更不做惯导误差状态滤波。

相位这一侧的模型是确定的。给定光纤环半径 R、匝数 N、真空波长 λ 与输入角速度 Ω，光纤总长度为 L = 2π·R·N，Sagnac 相位差 Δφ = 4π·R·L·Ω / (λ·c)，其中真空光速取固定常数。半径、匝数、波长任一小于等于零都要以带原因的错误 JSON 拒绝。服务要内置一份约两百米光纤长度的线圈参考配置，在地球自转量级的角速度下它应给出一个可被检出的微弧度级相位，供人快速核对量纲与系数。

标定这一侧是相位的逆过程。开环标度因数 K = 4π·R·L / (λ·c)，由相位反推的角速度为 Ω̂ = Δφ / K。当开环相位的绝对值接近 π 时存在测量模糊，服务必须显式给出模糊警告，绝不能悄悄把相位折叠到错误象限而返回一个看似正常的角速度。闭环偏置修正可以只做很薄的一层，但开环的正算与反演这条主链路必须先完整走通。

几条交叉关系要同时成立并且可测：只把角速度反号、其余不动，相位随之反号而绝对值不变；在匝数不变的前提下把环半径加倍，光纤总长也随之加倍，相位变为原来的四倍；只把波长加倍，相位减半；半径取零则报错。这些关系里最容易踩的坑是把光纤总长当成一圈周长而漏掉匝数，导致标度因数差了 N 倍，服务必须回避这个错误。

接口上区分两类调用：一类给定几何与单个角速度，返回相位、标度因数与反演出的角速度；另一类在同样的几何下扫过一组角速度网格，返回相位随角速度变化的采样序列——这条序列必须是逐点真算出来的，不允许用一条过原点的直线糊弄。同一进程里两组不同线圈配置的计算结果各自隔离，不得相互渗透。把环长与相位、标度与反演、角速度扫描、模糊判定、输入校验拆成互相独立的模块，并附自动化测试，重点锁住反号对称与半径加倍这两条。

技术栈方面，运行时选定为 Node.js 20，全程以 TypeScript 编写并编译成可直接执行的产物，HTTP 层交给 Fastify 承载。工程要能用一份 Dockerfile 构建出镜像、容器启动后监听固定端口对外提供接口，测试脚本随仓库一并交付、可在容器内运行。代码按职责切分为多个模块文件，几何计算、相位与标度、扫描、校验分别独立，不要把全部逻辑堆进单一入口文件。
